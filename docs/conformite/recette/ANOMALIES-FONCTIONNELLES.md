# Registre des anomalies de recette fonctionnelle

Tenu par : qa2. Une anomalie fonctionnelle (ANO-F) est un écart **reproductible** entre la GED
intégrée (branche `ct/qa2`, partie de `conformite-technique` à bc371ad) et le **Dossier d'analyse
des besoins fonctionnels V3** (le PDF fait foi), constaté du point de vue d'un utilisateur, par
l'API ou à l'écran. Les décisions actées de `DECISIONS-REVUE-TECHNIQUE.md` priment sur le PDF.
La recette technique des lignes « Livré » (registre `ANOMALIES.md`, tenu par qa) n'est pas refaite
ici.

Gravité et statuts : mêmes définitions que `ANOMALIES.md` (Bloquante, Majeure, Mineure ;
`Ouverte` → `Corrigée` → `Vérifiée` ou `Rouverte`).

Répartition proposée : écrans d'administration et d'exploitation → **dev4** ; écrans utilisateur
→ **dev5** ; écarts du back-end → membre du lot (dev1 : données, identité, autorisation ;
dev2 : traçabilité, exploitation, API ; dev3 : fichiers, OCR, recherche, cycle de vie) ;
arbitrage du Maître d'Ouvrage → **pm**.

Scripts : `recette/fonctionnel/` (voir son README). Identifiants « F-xx » : lignes de la matrice
fonctionnelle, numérotées dans l'ordre de `MATRICE-FONCTIONNELLE.md` (voir
`RESULTATS-FONCTIONNELS.md`).

| ANO-F-001 | F-09 — §3.2 p. 6 et 7, §4.6.5 p. 19 | Majeure | Le rôle système **Agent d'archive** est livré sans **Valider**, **Diffuser** ni **Purger** (composition : Archiver, Consulter, Déplacer, Déposer, Modifier, Supprimer, Voir privé).
